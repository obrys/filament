## Changes Made

- `src/Filament.Api/Pdf/LabelPdfGenerator.cs` (rewritten per plan D1'–D5'):
  - Tiling: `LabelsPerPage = 21`; `Paginate` chunks the expanded label list into pages of 21; each page is A4 with 4.95 mm left/right margins (Deviation 1), 5 mm top/bottom content padding, and rows of `ConstantItem(66 mm)` labels separated by `ConstantItem(1 mm)` gaps with a single trailing `RelativeItem()` per row (the verified QuestPDF-safe row structure — see Probe Evidence).
  - Panel: 66 × 35 mm, 0.5 pt border (cut guide), 2 mm inner padding, four equal 7.75 mm text bands (brand 11 pt bold / `material · type` 9 pt / colour 9 pt with optional inline swatch / spool ID 14 pt bold) and a 30 × 30 mm QR (QRCoder, ECC M) overlaid right-centred via `Layers` (primary text layer, then the QR layer, so the opaque white QR always paints over spilled text).
  - Font fitting (pure functions, public for unit testing): `FitFieldFont` (0.5 pt steps from the base size to the 8 pt floor; fits when every wrapped line estimates ≤ column width AND the line count fits the band), `MaxLines` (band holds two lines at 9.5 pt and below, one above — Deviation 2), `WrapLines` (greedy word wrap at a 0.7 em character estimate; overlong words keep their own line; truncated only in spill mode at the 62 mm / 57.77 mm inner widths), `BudgetLines` (caps a band at `MaxLines` lines).
  - Spill: a field that cannot fit the 32 mm column at 8 pt wraps at the full inner panel width, so its lines render under the QR's white background; the spool ID (4 generated characters) always fits at its 14 pt base.

## Deviations From Plan

1. **Left/right page margin is 4.95 mm, not 5 mm (0.05 mm off nominal, inside the ±0.5 mm tolerance).** QuestPDF 2024.12.0's A4 page is exactly 595 pt wide (209.903 mm; the PDF's `/MediaBox` is `[0 0 595 842]` — the spec's own AC-1 constant), so at 5 mm side margins the content width is 199.906 mm, which is 0.094 mm short of the 200 mm required by three 66 mm panels plus two 1 mm gaps, and QuestPDF fails with a `DocumentLayoutException`. At 4.95 mm the content width is 200.003 mm: the 66 mm panels and 1 mm gaps are kept exact, and a single trailing `RelativeItem()` per row absorbs the 0.003 mm remainder (or the whole empty space on 1–2 label rows, keeping short rows left-aligned). Observed: leftmost panel at 4.95 mm, rightmost edge at 205.04 mm, top row at 9.95 mm (both within ±0.5 of the spec values, which the e2e asserts).
2. **Hard line budget per text band (plan open-decision D3'/D4').** A band renders at most two lines at 9.5 pt and below, one line above. Probe evidence: three lines in a band push page content across a page break (probe J3), and the 11 pt band holds exactly one line (J9), while two 8 pt lines are safe (J7/J8). Consequence: for a pathological field set where three budgeted lines would be needed, `BudgetLines` drops the overflow lines instead of breaking the page; the always-visible spool ID and the 8 pt floor (spec D3/D5) are unaffected.
3. **AC-6's 128+ character e2e scenario is infeasible through the full stack; the e2e uses the longest storable values.** The schema caps the fields at brand 64, material 32, type 32, color 64 (`FilamentDbContext` `HasMaxLength`), so the API cannot return a 128+ character label field. The e2e test therefore creates a type with 64/32/32/64 character single-word values (same behaviour: floor + spill + ID visible). The 128+ character requirement itself stays enforced against the label generator by the unit layer, which uses 200 character fields (`Generate_NoFontSmallerThanEightPt`, `Generate_Spill_KeepsGlyphsInsideThePanel`, `Generate_QrPaintedAfterTextLabel`). Changing the schema is out of scope for this change.
4. **Shorter seed field values (test data, not product).** The `unique()` seed values were ~33–34 character single words (no spaces); the new 32 mm text column plus 8 pt floor renders single-word fields in full only up to ~29 characters, and several unchanged label-text tests match the full field strings (they would fail on silently truncated text). `unique()` now produces `prefix-<pid % 10000>-<unix ms>-<counter>` (still matching the `unique.spec.ts` contract: three numeric groups, 1000 distinct values, same-millisecond distinctness) and the seed prefixes are two letters, keeping values ≤ ~26 characters. `unique.spec.ts` and all other specs pass unchanged.
5. **Probe evidence (planned design settled by isolated probes, recorded per D1').** QuestPDF 2024.12.0 row layout constraints discovered while choosing the grid structure: an explicit-width element inside a relative slot throws on floating-point constraint conflicts (slot width computed as (200−2)/3 mm vs the explicit 66 mm demand), and equal-weight relative gaps split *all* leftover space (a two-label row's single gap ballooned to ~34 mm). The working row structure is `ConstantItem(66 mm)` per real label + `ConstantItem(1 mm)` gaps between real labels + one trailing `RelativeItem()` (probes I3/J7/J8; failing variants I2/J3/J9). The `Layers` overlay was verified to write the QR region to the page content after the label's text regions (probe H1/H4), which is what makes "opaque QR painted last" hold.

No `web/` files were touched in this change, so the SPA gate is not re-run beyond the e2e suite that loads the SPA.

## Limitations And Follow-Up

- **PDF inspection code is coupled to QuestPDF's stream format** (single line-oriented content stream per page, `re`/`f` fills, `Tm`/`Td`/`Tj` text, 2-byte glyph CMaps, `/Type /Pages` tree) in two places: `tests/Filament.Api.Tests/PdfProbe.cs` and `e2e/tests/fixtures/pdf.ts`. A QuestPDF upgrade that changes the output format needs both adjusted; the layer is isolated in one file each, and the page-count tests guard pagination independently of the parsers.
- **Font fitting uses a 0.7 em average character width and `MaxLines` uses a 1.2 line-height factor.** Both are conservative for the Lato subsets in use (the estimate overestimates width, so real re-wrapping can only add lines, and the line budget keeps two 8 pt lines inside the 7.75 mm band — empirically confirmed for the worst observed re-wrap, a 30-character all-`M` word physically wrapping to two lines that stayed inside the band). A switch to a much wider font or a different band height should re-check these constants and the `MaxLines` breakpoints (9.5 pt / 10 pt).
- **The 4.95 mm side margin means "5 mm" is not bit-exact in the output** (0.05 mm deviation, invisible on paper, inside the spec's ±0.5 mm tolerance) — see Deviation 1.
- **Seed names are short unique words** (`eb-…` etc.) so the full strings render on the new label; they are still visible in the SPA lists/tables, so the UI-facing specs are unaffected.
- **One flaky observation during verification:** the unchanged "print opens a new tab with copies=K" e2e test failed its first attempt once (needle missing in the re-fetched body) and passed on retry in the same run; all subsequent runs (including the final full run) were clean. The helper and assertions are untouched by this change; if it recurs it should be investigated in `printViaDialog`'s response capture.
